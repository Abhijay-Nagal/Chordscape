0 · At a glance

What it costs

  • US$25 one-time Google Play developer registration fee (pay by card).
  • Free hosting for your privacy policy - GitHub Pages from your Keyscape repository.
  • Optional: a real Android phone or tablet for testing (you probably already have one).
  • No yearly fee. Google takes 15% of sales only if you ever charge money - Keyscape is free, so nothing.

How long it takes

  • Your active work: about 4-6 hours spread over the weeks.
  • Calendar time: typically 3 to 5 weeks for a brand-new personal account, mainly because Google requires a 14-day closed test with at least 12 testers before you may publish to everyone.
  • Each Google review: usually hours to a few days; occasionally up to 7 days or longer.

What you upload

  • dist/Keyscape-1.4.5-play-store.aab - the app bundle (already built and signed).
  • Graphics from docs/play-store/ (icon, feature graphic, 8 phone and 8 tablet screenshots).
  • Texts from docs/play-store/listing.md (copy and paste).

What you need ready

  • A Google account you will keep for years (ideally a dedicated one, e.g. keyscape.dev@gmail.com).
  • A government photo ID (passport, Aadhaar, driving licence…) for identity verification.
  • A phone number and a contact email.
  • 12 or more friends or family with an Android phone who will install your test version.

The big picture

Publishing happens in four phases. Phases 1 and 2 are setup you do once; phase 3 is the mandatory testing period for new personal accounts; phase 4 is the public launch.

Words you will meet: Play Console = Google's website for publishing (play.google.com/console). AAB (Android App Bundle) = the file you upload. Track = a release channel (internal, closed, open, production). Rollout = making a release available to users.
If you register an organization account (a company with a D-U-N-S number), Google does not require the 14-day closed test - you can go from Phase 2 straight to Phase 4. For an individual, the personal account is simpler and the testing period is a good quality check anyway.

What is already done in your project

Google checks the app file automatically when you upload it. These technical requirements have all been prepared for you:

  • Android App Bundle built in release mode: dist/Keyscape-1.4.5-play-store.aab (≈35 MB; Google's limit is 200 MB). Checked on 11 October 2026: signature verified, all tests pass.
  • Signed with your own upload key (RSA-4096, valid ~27 years) - keystore/pianoquest-upload.jks. Release builds pick it up automatically through keystore.properties. (The certificate's internal name is "PianoQuest", the project's working title - users never see it, because Google re-signs the app.)
  • Target API level 36 (Android 16) - meets Google's current rule for new apps; minimum Android 8.0 (API 26) so it runs on ~97% of active devices.
  • 16 KB memory-page compatible - the only native library (from AndroidX) is 16 KB aligned, as Google requires for apps targeting Android 15+.
  • No permissions requested - no internet, location, contacts, storage or microphone access (verified in the built app: the only entry is an Android-internal permission that every modern app has). This makes the Data Safety form trivial and reviews smooth.
  • Package name is free - on 11 October 2026 no app on Google Play used com.keyscape.app.
  • Code shrinking/obfuscation (R8) enabled; debuggable turned off; version 1.4.5 (versionCode 13).
  • Privacy policy written: docs/privacy-policy.html (you only need to put it online - Step 4). An in-app copy is under More → About, privacy & licences.
  • Licences and credits for all music, samples, pictures and fonts are shown in the app (required by the Creative Commons licences).
  • Store graphics in the right sizes and formats (24-bit PNG without transparency, as Google requires): app icon, feature graphic, 8 phone and 8 tablet screenshots in docs/play-store/.
  • Promo video: promo/out/keyscape-promo-sample2-1080p60.mp4 (2:16, 1080p60) with a ready YouTube title, description and thumbnail.
  • Source code on GitHub: github.com/Abhijay-Nagal/Keyscape (the keystore and passwords are deliberately not in it).

Step 2 - Protect your upload key

10 min Every build you upload must be signed with the same upload key. Yours is ready in the keystore folder of the project.

This system is called Play App Signing and is mandatory for new apps. Because Google holds the real app-signing key, losing your upload key is recoverable (Google support can reset it), but it costs days of delay - so back it up now.

1
Open keystore/README-KEEP-SAFE.txt - it contains the key alias and the password.
2
Copy the whole keystore folder and the file keystore.properties to two safe places: e.g. an encrypted USB drive and a password manager (as attachments) or a private, encrypted cloud folder.
3
Save the password in your password manager too.
Never put the .jks file or its password on GitHub, in an email or in a chat. They are already excluded from git via .gitignore. Your project folder lives in OneDrive - that is a backup, but make sure your Microsoft account has 2-step verification on.
During the first upload, Play Console asks how to set up app signing. Choose the default: "Use Google-generated key" (Play App Signing). Nothing else to configure.

Step 3 - Build the app bundle (.aab)

5 min The current bundle is already built: dist/Keyscape-1.4.5-play-store.aab. You only need to rebuild when you change something (package name, code, content).

How to rebuild

Open a terminal (PowerShell) in the project folder and run:

cd C:\Users\HP\OneDrive\Desktop\my_projects\Keyscape
.\gradlew :composeApp:bundleRelease

The new bundle appears at composeApp\build\outputs\bundle\release\composeApp-release.aab. It is signed automatically with your upload key (thanks to keystore.properties).

Every update needs a higher version code

Google refuses a bundle whose versionCode was used before. Before each new upload, open composeApp/build.gradle.kts and raise both numbers:

defaultConfig {
    applicationId = "com.keyscape.app"
    versionCode = 14         // was 13 - always +1
    versionName = "1.4.6"    // what users see
}

Also update packageVersion (same file, Windows builds) and VERSION in composeApp/src/commonMain/kotlin/com/pianoquest/app/AppInfo.kt so the About screen matches.

Want to try the release build on your own phone first?

Use the ready-made dist/Keyscape-1.4.5-android.apk (signed with the same upload key): copy it to the phone and open it (allow "install unknown apps" once). Uninstall it before installing from Google Play later - the Play version is signed by Google's key, so Android treats them as different signatures.

Your phone already has this test build (installed over USB while the promo video was made). Before you install Keyscape from the Play Store link in Step 8, uninstall it (long-press the icon → Uninstall), or the Play Store will say it cannot install the app. Uninstalling also clears the practice progress made during testing.
Test on a real phone: play a few songs (Note Wait, Listen and Practice modes, all three guide modes), connect your MIDI keyboard, try Free Play with 88 keys, switch dark mode. Fix anything odd before the closed test - testers' first impression matters.

Step 4 - Publish the privacy policy online

20 minfree Google requires a public web link to a privacy policy for every app - even apps like Keyscape that collect nothing. Your policy is written: docs/privacy-policy.html. You just need to host it.

Option A - GitHub Pages (recommended, 2 minutes)

The policy is already in your public repository at docs/privacy-policy.html.

  1. Open github.com/Abhijay-Nagal/Keyscape → Settings → Pages (left menu).
  2. Source: Deploy from a branch. Branch: main, folder: /docs. Click Save.
  3. Wait 1-2 minutes, then open https://abhijay-nagal.github.io/Keyscape/privacy-policy.html - you should see "Keyscape - Privacy Policy".
  4. That address is your privacy policy URL.

The repository must stay public for free GitHub Pages.

Option B - Google Sites

  1. Go to sites.google.com → Blank site.
  2. Title: "Keyscape Privacy Policy".
  3. Open privacy-policy.html in your browser, select all text, copy, and paste it into the site.
  4. Click Publish, choose a web address, make it public.
  5. Copy the URL (e.g. sites.google.com/view/keyscape-privacy).
The link must open a normal web page (not a PDF download, not a Google Doc that requires sign-in) and must mention the app name. Keep it online for as long as the app is published.
The contact email in the policy is nagalabhijay@gmail.com. If you create a dedicated developer email, change it in both privacy-policy.html and the Play Console.

Step 5 - Create the app in Play Console

10 min In Play Console click Create app (top right of "All apps").

Free is permanent. Once an app is published as free it can never be changed to paid (you could add in-app purchases later). Keyscape is designed as a free app.
Check the name isn't already used by a well-known app: search the Play Store for "Keyscape" first. If needed, pick a variant such as "Keyscape - Piano School". The store name can be changed later; the package name cannot.

After creating the app you land on the Dashboard. It shows a checklist titled "Set up your app" - Steps 6 and 7 of this guide complete that checklist.

Step 9 - Closed test: 12 testers × 14 days

14 days minimum Google requires new personal accounts to run a closed test with at least 12 testers who stay opted in for at least 14 days in a row before production access is unlocked.

Set it up

1
Testing → Closed testing → use the default track ("Alpha") → Create release → choose Add from library and pick the bundle you already uploaded (or upload it again). Add release notes.
2
Testers: easiest is a free Google Group (groups.google.com → Create group, e.g. keyscape-testers@googlegroups.com, set "Who can join: anyone with the link"). Add the group's email in Play Console. Alternatively add an email list.
3
Select countries (all), then Review release → Start rollout to Closed testing. This first closed release is reviewed by Google (usually 1-3 days).
4
Send testers both links: the Google Group link (to join) and the opt-in link from the Testers tab. Each tester must: join the group → open the opt-in link → tap "Become a tester" → install Keyscape from the Play Store link.

Finding 12+ testers

  • Family and friends with Android phones - ask 15-20 to be safe in case someone drops out.
  • Music teachers, piano students, choir or school groups - they'll also give useful feedback.
  • Developer communities exchange testers (e.g. Reddit r/AndroidClosedTesting, "testers community" apps). Only use trustworthy sources.

During the 14 days

  • Ask testers to keep the app installed and open it every few days (Google looks at real engagement).
  • Collect feedback (Google Form or a WhatsApp group). Note what you fixed - you'll describe it in Step 10.
  • If you fix bugs, upload a new build (higher versionCode) to the closed track - this does not reset the 14 days.
  • Check Dashboard: it shows "X testers opted in" and the days counted.
The clock needs 12 testers opted in continuously. If someone leaves on day 10 and you drop to 11, the count can restart. Recruit spares.

Step 10 - Production access & launch

When the 14 days are done, the Dashboard shows "Apply for production". You'll answer a short questionnaire. Be specific and honest - vague answers are the main cause of rejection.

Typical questionExample answer for Keyscape
How did you recruit testers?"Friends, family and two local piano students; 16 testers joined through a Google Group."
How easy was it to recruit?Choose honestly (e.g. "Neither easy nor difficult").
Describe the engagement"Testers completed lessons in Piano Foundations, played songs in Note Wait, Listen and Practice modes, connected two USB MIDI keyboards, and used Free Play daily."
Feedback summary"Requests for a bigger keyboard on small phones and a MIDI reconnect button; a crash when … was fixed in 1.1.1."
Who is the app for?"Self-learners of all ages who want a complete piano course from beginner to advanced, with or without a digital piano."
How is it different / valuable?"Structured courses (172 lessons), 222 pieces including 184 complete public-domain scores with Easy/Medium/Hard levels, MIDI keyboard support, no ads and no data collection."
Changes made from testingList your real fixes (Step 9 notes).
Is the app ready for production?Yes, and explain how you know (testing on several phones, no crashes in Android vitals).

Google typically answers within 7 days. If declined, you'll get feedback; continue testing and apply again.

Launch

1
Production → Create new release → Add from library (the bundle your testers used) or upload the newest bundle.
2
Release notes, e.g. "First release of Keyscape: 14 courses with 172 lessons, 222 pieces with Easy, Medium and Hard levels, three guide modes, practice tools, composer storybooks and USB MIDI keyboard support."
3
Optional but wise: staged rollout - start at 20%, watch for crashes for a day or two, then increase to 100%.
4
Review release → Start rollout to Production. Then open Publishing overview and click Send for review if changes are waiting.
When approved you'll get an email and the app appears at play.google.com/store/apps/details?id=com.keyscape.app. It can take a few hours before it shows up in search.

After launch: updates & upkeep

Releasing an update

  1. Make your changes; raise versionCode (+1) and versionName (Step 3).
  2. Run .\gradlew :composeApp:bundleRelease.
  3. Upload to Closed testing first if it's a big change, then promote to Production; small fixes can go straight to Production.
  4. Use a staged rollout for larger updates.

Watch these regularly

WhereWhy
Quality → Android vitalsCrash and "App not responding" rates. Google lowers visibility of apps with crash rates above ~1.09% or ANR rates above ~0.47%.
Ratings and reviewsReply politely - replies are public and improve trust.
Inbox / emailPolicy notices with deadlines. Missing a deadline can remove the app.
StatisticsInstalls and uninstalls by country and device.

Yearly duties

  • Target API update: Google raises the required target API every year (around 31 August). Keyscape targets API 36 now; plan to update to API 37 by August 2027. This needs a newer Android Gradle Plugin (version 9) - budget a day for it.
  • Re-confirm declarations (Data safety, target audience) when Google asks.
  • Keep the privacy policy URL online and your contact details current.
  • Log in to Play Console at least once a year - inactive accounts can be closed.
Optional growth ideas: translate the store listing (Store presence → Translations), add a short promo video, create a custom store listing for countries, and ask happy users to leave a rating.

Rules to keep in mind

Intellectual property

Only publish content you have the right to use. Keyscape is prepared for this:

  • Complete classical scores: public domain or Creative Commons (Mutopia Project), credited in the app.
  • Grand-piano samples: Salamander (CC BY 3.0), credited.
  • Pictures: public domain / CC0, credited.
  • Modern pop songs: chord progressions only - never add copyrighted melodies, lyrics or recordings (e.g. full "River Flows in You" or "Shape of You" scores). That's a common reason for takedowns.
  • MIDI files users import stay private on their own device.

Metadata & impersonation

  • Don't use other apps' names ("Perfect Piano", "Simply Piano", "Yousician") or logos in the title, description or screenshots.
  • Screenshots must show the real app.
  • No fake reviews, no incentivised ratings, no keyword stuffing.

User data

  • If you ever add analytics, crash reporting, ads, accounts or internet features, you must update the Data Safety form and the privacy policy before releasing that version.
  • Adding the INTERNET permission alone changes nothing to report, but any SDK that sends data does.

Account health

  • One account per person is enough - never create a second account to get around a suspension.
  • Respond to Google within the deadlines in policy emails.
  • Use accurate developer information.

Children

If you later choose an under-13 audience, the app must follow the Families Policy (no ads that aren't certified, no data collection). Keyscape already complies, but the review is stricter.

Money (if ever)

Charging or selling in-app content requires a payments profile (merchant account) and Google Play Billing. The free app as built needs none of this.

FAQ

Can I publish the Windows version on the Play Store? No - the Play Store is for Android (and ChromeOS, which runs your Android app). The Windows installer in dist could go to the Microsoft Store separately (one-time fee ~US$19 for individuals) - a different process.

Can I change the app after publishing? Yes - everything except the package name and "free" status. Upload a new version any time.

Will Google see my source code? No, only the compiled bundle.

Do I need a company or GST registration? Not for a free app on a personal account.
